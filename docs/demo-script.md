# Three-minute judge demo

## 0:00–0:25 — Problem and promise

Open Overview. Say: “Industrial catalog rows are incomplete, while source facts are fragmented and sometimes contradictory. CatalogIQ turns those rows into defensible product intelligence: every value has evidence, confidence and a human decision trail.” Point out DEMO MODE · LOCAL · SECURE and the LIVE-provider fallback.

## 0:25–0:55 — Truthful data profiling

Open Dataset Profile and upload the organizer input CSV. Show 1,000 rows, six columns, per-field placeholders, duplicate part numbers/descriptions, zero full-row duplicates and measured processing time. Explain that the upload is processed locally and not retained.

## 0:55–1:35 — Evidence Ledger and conflict

Open Enrichment Review. Select the synthetic Northline record and run DEMO enrichment. Open the voltage field. Show preserved 120 V and 240 V candidates, `CREDIBLE_SOURCE_CONFLICT`, confidence, and synthetic `demo://` evidence. Explain that CatalogIQ withholds the value instead of guessing.

## 1:35–2:10 — Human review and regeneration

Run the high-confidence Aster record. Correct Manufacturer to “Aster Manufacturing,” add “Verified during judge demo,” and save. Open Mobile Description to show deterministic regeneration. Display audit history, then approve the product.

## 2:10–2:35 — Delivery

Download the 252-column CSV and audit JSON. Explain that supported approved facts use the organizer’s exact column order, unsupported and rejected fields remain blank, and the audit file carries evidence, validation, conflicts and decisions.

## 2:35–3:00 — Quality and honest boundary

Open Quality Centre. Show real persisted metrics and test inventory. State: “The supplied two expected rows support a prototype benchmark only. After excluding facts absent from input evidence, the supported product-name comparison is 2/2; this is not general accuracy.” Close with the ₹0 offline architecture and optional server-side LIVE provider.
